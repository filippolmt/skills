# Vendor a shared skills tree on `main`, read by Claude, pi and Codex

This marketplace is built on one principle: external skills are **referenced**
upstream via `git-subdir`, never copied here. Serving a second harness breaks it —
but not for the reason [ADR-0007](0007-vendor-a-generated-codex-catalog.md) gave.
Both [pi](https://pi.dev) and Codex implement the
[Agent Skills standard](https://agentskills.io/specification) and read a plain
`SKILL.md` with the frontmatter we already ship. A skill of ours is a skill of
theirs, byte for byte. What neither can do is **address a subdirectory of somebody
else's repository**, which is exactly what all 81 of our `git-subdir` entries are.

- pi clones a whole repository: its parsed `GitSource` carries `repo`, `host`,
  `path`, `ref`, `pinned` and no subpath, with `path` shaped exactly `owner/repo`.
  Subdirectory selection happens *after* the clone, as a **package filter**.
- Codex's marketplace does accept a `git-subdir` source with `url`/`path`/`ref`/`sha`
  — the same entry shape as ours — but every plugin needs a manifest, and only **4**
  of our 79 entries pointed at a folder that has one. Worse, the failure is quiet:
  *"If Codex can't resolve a marketplace entry's source, it skips that plugin entry
  instead of failing the whole marketplace."*

So there is no referencing route to either. We **materialise** the skills ourselves,
once, into a tree all three agents can read.

## What was decided

**A vendored skills tree at `skills/`.** One directory per portable skill, holding
the upstream skill copied at the `sha` its catalog entry pins, its upstream licence,
and a `SOURCE.md` recording repository, `sha` and licence. Generated by a script,
checked in CI, never hand-edited — a **catalog projection** in the same sense the
README table already is.

That position is not a preference; it is the only one all three agents reach:

| | how it finds `skills/` |
|---|---|
| Claude | a plugin's **mandatory** `<plugin-root>/skills/` — this repo is itself the `skills-tree` plugin, manifest at `.claude-plugin/plugin.json` |
| pi | its package **convention directory**, `<root>/skills`, served with no manifest field at all |
| Codex | a plugin's default skill root, and it reads `.claude-plugin/plugin.json` as a manifest, so it needs no `.codex-plugin/` of its own |

Claude is what forces it. It does not scan the standard's shared locations, and a
Claude plugin **cannot declare** where its skills live: no `skills` field exists in
`plugin.json`, and every component directory must sit at the plugin root.

**`.agents/skills` is a committed symlink to it.** That is the Agent Skills
standard's shared path, and both pi and Codex scan it by themselves — user scope
`~/.agents/skills`, and repo scope in the working directory and its ancestors. The
symlink is what keeps a zero-install route without a second copy; verified against
both agents, including that Codex resolves the root through it to the real path.

This is the shape of `cloudflare/skills`, the multi-harness repo this catalog already
depends on: one tree at `skills/`, a manifest per harness beside it, and a
marketplace entry whose `source` is `"./"` — the repo itself. The symlink is ours.

**Explicitly not the mirror shape.** `heygen-com/hyperframes` duplicates the same
skills into `.claude/skills/` *and* `.agents/skills/` as real directories, and guards
the duplication with `scripts/check-skill-mirror.mjs`, a byte-identical comparison
whose header states the failure mode exactly: *"each CLI reads only its own path.
They must stay in lockstep or one CLI will silently ship a stale skill."* That guard
exists because the copies are maintained by hand. With a generator there is nothing
to mirror: one copy, and `gen-skills-tree.js --check` is the guard.

**On `main`, not on a release branch.** ADR-0007 kept the generated tree off `main`
for reviewability. That reasoning survives; its remedy does not. From pi's resolver:

```
pinned: Boolean(ref)
// Pinned npm versions are fixed. Pinned git refs are configured checkout targets,
// so include them to reconcile an existing clone when the configured ref changes.
```

Any ref at all — branch, tag or commit — makes a pi source *pinned*, and `pi update`
never moves a pinned source forward. Only a **ref-less source** tracks `origin/HEAD`,
which is the **default branch**. A release branch as a ref would therefore never
auto-update. The noise is isolated by *when* generation runs instead: Renovate's PR
stays the one-line `sha` change it is today, and regeneration lands afterwards in its
own `chore: regenerate skills tree` PR.

**How it is consumed.**

- **Claude**: `/plugin install skills-tree`, one plugin carrying the whole tree.
- **pi, globally**: `pi install git:github.com/filippolmt/skills` — deliberately with
  no ref, so `pi update` moves it.
- **pi, per project**: a `.pi/settings.json` committed in the consuming repository.
  pi auto-installs a project's packages on startup once the project is trusted, which
  is the closest thing it has to Claude's `enabledPlugins`.
- **pi and Codex, with nothing installed**: the tree is already on the standard path,
  inside a checkout, or globally by symlinking it to `~/.agents/skills`. `git pull` is
  the update.

**Selection belongs to the user, so we ship snippets.** For pi, which skills are
active is a package filter (`{"source": "…", "skills": ["skills/*", "!skills/…"]}`
with globs and `+`/`-` overrides) in a settings file this repository does not own. For
Codex it is `[[skills.config]] path = "…" enabled = false` in `~/.codex/config.toml`.
The generator emits the snippets; `pi config` toggles at runtime. We recommend, we do
not install.

**Skills only.** Measured against the 17 upstream repositories at their pinned
`sha`s, install-independently: the entries hold one `SKILL.md` each, **zero
commands**, 10 subagent files across 3 entries (`api-scaffolding`, `impeccable`,
`shell-scripting`) and **one** `hooks.json`. Neither pi nor Codex has subagents a
plugin can ship, neither has `dependencies`, and pi has no declarative hooks at all
(TypeScript extensions only). So the guards, `mode-router` and every bundle have no
counterpart, and the 10 subagent files do not travel.

**Adaptation is an overlay, not a fork**, and **failures are loud** — both carried
over from ADR-0007 unchanged. A harness-specific edit lives beside the byte-identical
copy as a unified diff, so upstream moving under it makes `git apply` fail instead of
silently freezing a skill. An entry whose `path` will not resolve at its `sha` fails
the whole generation.

## Considered and rejected

- **Referencing upstream directly** — `pi install` each of the 17 repositories, or a
  Codex marketplace pointing `git-subdir` at each entry. It is the only shape that
  keeps this repo's founding principle, and it fails on all sides: for pi, ref-less
  means tracking upstream's default branch and losing our pins entirely while ref-ed
  means never auto-updating, and either way a whole-repo clone drags in the upstream
  skills we deliberately did not catalogue; for Codex, 75 of 79 entries point at a
  folder with no plugin manifest, so the entry is skipped in silence.
- **The tree at `.agents/skills/`**, the standard's shared location. It was chosen
  first, on the strength of pi and Codex scanning it natively — but Claude scans
  neither shared location and cannot be pointed at one, so that position serves two
  agents out of three. Keeping it as a symlink preserves everything it bought.
- **A root `skills/` plus mirrored copies** per harness path, the hyperframes shape.
  See above: a generator removes the need.
- **A release branch**, as ADR-0007 chose. A branch is a pinned ref for pi.
- **A second repository** whose default branch is the generated tree. It keeps `main`
  pristine and auto-updates correctly, but splits the `sha` bump from the artifact it
  produces.
- **Pointing an agent's settings at `~/.claude/skills`**, which pi's docs suggest for
  cross-harness use. It presumes Claude is installed and its plugins already fetched;
  each agent has to work on a machine where it is the only one.

## Consequences

- **We redistribute other people's code.** Today this repo references; from here
  their source is in our history, permanently. All 17 upstream repositories carry a
  licence, so nothing is excluded on that ground today — the generator still reads
  each licence, copies it next to the skill, and refuses a repository that has none.
  This is the least reversible part of the decision, which is why the first release
  is a five-skill pilot with no overlays.
- **On Claude the two routes are exclusive.** `skills-tree` ships the same skills the
  catalog offers entry by entry, so installing both gives two of each. Documented,
  not enforced: `check-name-collisions.js` scans `plugins/*/` and `.claude/skills/`,
  and extending it here would flag every intentional pair as an error.
- **Codex namespaces the tree's skills.** Because it reads `.claude-plugin/plugin.json`
  as a plugin manifest, the skills arrive as `skills-tree:tdd` rather than `tdd` when
  the plugin root is in scope. Through `~/.agents/skills` — a scan root, not a plugin
  — they keep their bare names.
- **Codex already sees our catalog, and mostly skips it.** Codex reads
  `.claude-plugin/marketplace.json` as a legacy-compatible marketplace — it is third
  in its list of catalog paths. Pointing Codex at this repo surfaces the catalog, of
  which nearly every entry resolves to a folder with no plugin manifest, each skipped
  in silence. The tree is what makes the repo useful to it.
- **Codex refresh is gated on a manifest `version`, not on the ref.** There is no
  `codex plugin update`. A background refresh re-clones the configured ref but bails
  when the upstream `plugin.json` `version` equals the installed one, and a missing
  `version` becomes `"local"` on both sides. If the Codex *plugin* route is ever
  taken, the generator must bump that `version` on every regeneration; the scan-root
  route this ADR relies on is unaffected.
- **ADR-0007 is superseded.** What survived is named above: vendored copies, overlays
  as patches, loud failures, the licence rule. What did not: the release branch, and
  its claims about pi — pi does have git package sources and filters.
- **`sandbox-sdk` blocked the first generation** and is fixed in its own PR: the entry
  pinned a path upstream had split into `sandbox-stable`, `sandbox-next` and
  `sandbox-migrate-to-next`. Renovate bumps a `sha` and cannot see a renamed folder,
  and no check resolved a `path`, so the catalog stayed green over an entry that
  installed nothing. The generator is now that check.
- **Name collisions turn quiet.** On a duplicate name pi keeps the **first skill
  found** and warns; Codex drops skills from its prompt when the listing exceeds 2% of
  the context window, also with a warning. The generator refuses to write two skills
  under one name.
- **Project trust gates the repo scope.** pi loads `.agents/skills/` only after the
  project is trusted; Codex requires the user to trust plugin-bundled hooks
  separately, which a skills-only tree does not have.
- **CI grows, the local hook does not.** Generation clones 17 repositories; a
  `PostToolUse` hook that blocks an edit for a minute gets disabled within days.
